## ⚠️ 정정 — get_nearby_minbak RPC는 개별 마커용이 아님

`MapView.tsx`는 개별 매물 마커를 그릴 때 `get_nearby_minbak` RPC를 쓰지
**않았다**. 그 RPC는 "반경 내 개수"만 반환하는 집계 함수라 마커 좌표 목록을
줄 수 없다. 개별 마커는 `minbak_listings` 테이블을 좌표 필터 없이 통째로
`SELECT`하는 `/api/map/listings`를 썼다. 이식 시 두 가지를 목적에 맞게
분리해서 가져가야 한다.

- **개별 마커(지도에 점 찍기)** → 테이블 직접 조회 패턴 (아래 1번)
- **반경 내 개수 표시(패널 숫자)** → `get_nearby_minbak` RPC 패턴 (아래 2번,
  `/explore`에는 이미 이 패턴이 적용되어 있음 — `src/lib/data/analysisData.ts`,
  `src/app/api/competition/route.ts` 참고)

## 1. 개별 매물 데이터 조회 — `/api/map/listings` (삭제됨)

```ts
// src/app/api/map/listings/route.ts (원본, 삭제됨)
import { NextResponse } from 'next/server'
import { supabaseAdmin } from '@/lib/supabase/server'

export const dynamic = 'force-dynamic'

export async function GET() {
  const { data, error } = await supabaseAdmin
    .from('minbak_listings')
    .select('id, name, road_address, lat, lng')
    .eq('status', '영업') // ⚠️ 버그: 실제 DB 값은 '영업/정상' — 항상 0건 반환했음. 이식 시 .eq('status', '영업/정상') 또는 ilike('status', '영업%')로 수정 필요.
    .not('lat', 'is', null)
    .not('lng', 'is', null)
    .limit(3000)

  if (error) {
    return NextResponse.json({ error: '데이터를 불러올 수 없습니다.' }, { status: 500 })
  }

  return NextResponse.json(data ?? [])
}
```

**이식 시 체크리스트**
- `status` 필터 버그 수정 필수 (위 주석 참고, 2026-07-10 감사에서 발견 — 실제
  DB에는 `'영업/정상'` 값만 존재, `.eq('status', '영업')`은 0건 반환).
- 전국 3000건 한도로 조회했음 — 마포구 한정이면 `road_address ilike '%마포구%'`
  등으로 좁혀서 페이로드 축소 고려.
- 개별 숙소명(`name`)·정확 주소(`road_address`)는 공공데이터라 노출 가능
  (CLAUDE.md "개별 숙소 노출 정책" — 외도민은 상호·주소 노출 가능, AirROI만
  금지). `/explore`에 이식해도 이 원칙은 그대로 유지.

## 2. 개별 마커 렌더링 — `MapView.tsx` 패턴 (삭제됨)

```tsx
// 타입
interface Listing {
  id: string
  name: string
  road_address: string
  lat: number
  lng: number
}

// 클러스터 스타일 (3단계 — 개수 구간별 원 크기/색)
const CLUSTER_STYLES = [
  { width: '44px', height: '44px', background: 'linear-gradient(135deg, #1a56db, #0ea5e9)',
    borderRadius: '50%', color: '#fff', textAlign: 'center', lineHeight: '44px',
    fontSize: '13px', fontWeight: '700', boxShadow: '0 4px 14px rgba(26,86,219,0.45)' },
  { width: '52px', height: '52px', background: 'linear-gradient(135deg, #1e40af, #1a56db)',
    borderRadius: '50%', color: '#fff', textAlign: 'center', lineHeight: '52px',
    fontSize: '14px', fontWeight: '800', boxShadow: '0 4px 18px rgba(26,86,219,0.55)' },
  { width: '60px', height: '60px', background: 'linear-gradient(135deg, #1e3a8a, #1e40af)',
    borderRadius: '50%', color: '#fff', textAlign: 'center', lineHeight: '60px',
    fontSize: '15px', fontWeight: '800', boxShadow: '0 4px 20px rgba(30,58,138,0.6)' },
]

// 로드 — 페이지 진입 시 1회
const [listings, setListings] = useState<Listing[]>([])
useEffect(() => {
  fetch('/api/map/listings')
    .then(r => r.json())
    .then((data: unknown) => setListings(Array.isArray(data) ? (data as Listing[]) : []))
    .catch(() => setListings([]))
}, [])

// 렌더 — Map 컴포넌트 내부
<MarkerClusterer averageCenter minLevel={5} styles={CLUSTER_STYLES}>
  {listings.map(listing => (
    <MapMarker
      key={listing.id}
      position={{ lat: listing.lat, lng: listing.lng }}
      onClick={() => {
        kakao.maps.event.preventMap()
        setSelected(listing)
      }}
    />
  ))}
</MarkerClusterer>
```

**이식 시 참고**
- `/explore`(`ExploreMapView.tsx`)는 이미 에어비앤비 핀에 `MarkerClusterer`
  (`averageCenter`, `minLevel={4}`)를 쓰고 있음 — 동일 패턴이라 라이브러리
  로드(`useKakaoLoader({ libraries: ['clusterer'] })`)는 이미 되어 있어 추가
  설정 불필요.
- 에어비앤비 핀은 로즈 도트 커스텀 이미지 마커(`AIRBNB_PIN_IMAGE`, SVG data
  URI)를 쓰는 반면 외도민 마커는 기본 카카오 마커 + 클러스터 숫자 뱃지 스타일
  — 두 레이어를 동시에 켤 경우 시각적으로 구분되는 마커 스타일을 유지할 것.
- 클릭 시 개별 숙소 상세(이름·주소) 패널을 띄우는 `InfoPanel` 패턴은 원본
  `MapView.tsx` 전체(git 이력)에서 확인 가능 — 필요하면 `git show
  <삭제_전_커밋>:src/components/map/MapView.tsx` 로 복원해서 참고.

## 3. 반경 내 개수(집계) — `get_nearby_minbak` RPC — 이미 `/explore`에 있음

개별 마커가 아니라 "이 위치 기준 N개" 숫자가 필요하면 새로 만들 것 없이 기존
패턴 재사용:

```ts
// src/lib/data/analysisData.ts 참고 (POST /api/analysis에서 사용 중)
const { data } = await supabaseAdmin.rpc('get_nearby_minbak', {
  user_lat: lat,
  user_lng: lng,
  radius_m: radiusM,
})
```

동 단위 사전 캐시(패널 상시 표시용)는 `npm run fetch:minbak-count` →
`data/seoul-mapo-dong-minbak-count.json` — 이 값과 개별 마커 개수는 소스가
같은 테이블(`minbak_listings`)이지만 집계 방식(동 폴리곤 vs 좌표 반경)이 달라
정확히 일치하지 않을 수 있음(2026-07-10 확인: RPC 353건 vs 정적 캐시 서교동
343건 — 근사값 차이 있음, 이식 시 두 숫자가 다르게 보이는 게 정상임을
UI 문구에 반영할 것).
